## Listener evaluation — unexecuted with participants

Recruit 4–6 authorized listeners with mixed prior label familiarity; include mobile/Safari/Chromium and one keyboard-only task. Ask for consent for written observations; recording is optional and requires separate approval. Use a staging build, no personal inquiry or real purchase. Give tasks without teaching INFO/navigation. Record device/browser/build, time, independent completion, wrong-release plays, misidentified track/artist, hesitation points, help requests and direct quotes only if consented. Do not manufacture people/results from engineering smoke tests.

1. “Find a release that interests you in the archive and tell me which artist is associated with it.” Record whether missing profile context blocks discovery.
2. “Listen to that release, then tell me the title and credited artist of what you hear.” Correct selection, audible playback and identification must each be observed; a route opening or Play click alone is insufficient. For iframe, let participants read Bandcamp's own metadata; parent page cannot infer current track.
3. “Pause, resume, and move to another point. Visit an artist while listening, inspect Credits and the full release page, then open the Visualizer. Choose a second release, then return using Back.” Record internal-navigation continuity, understood release replacement/history behavior, drawer dismissal/focus, and consistent identity/support. Full departure/reload does not restore this in-memory playback session.
4. “Find where you could support this release.” Completion is finding the correct outbound Bandcamp destination; do not purchase. A click is a referral, never a confirmed sale.
5. “Find a way to send a booking/label inquiry.” Until destination/sender approval, mark this task blocked by product availability, not completed. After setup use approved fictitious staging text and record provider acceptance and recipient receipt separately.

Candidate acceptance: no wrong-release audio/identity, all independent listeners locate Listen/selector/support, keyboard user completes without focus loss, users understand unavailable-preview recovery. Target counts/thresholds require owner approval. Report results per participant, including failed/unexecuted tasks and uncertainty; no general audience/revenue/production-readiness inference.

## Observability limits

No analytics SDK, event endpoint, cookies, identity capture or silent tracking was added. Engineering evidence can observe local native media state/time, simulated analyser/teardown, selected URL/identity and outbound destination. It cannot observe purchases, actual iframe playback across origins without a supported signal, inbox receipt, editor publish or deployment from configuration alone. Any future referral counts need a deliberate approved instrument/consent policy; actual purchase conversion requires an authorized provider signal.
