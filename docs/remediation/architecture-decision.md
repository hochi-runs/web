# ADR 001 — explicit archive relationships and selected-track delivery

Status: decision-ready recommendation for owned delivery, October 9, 2026. The owner's later request authorized site-wide native-preview persistence and a release-credits drawer; these are implemented locally. No production database, vendor, ingestion pipeline, or transport migration has been shipped. WordPress remains the editorial tool. Implemented foundations include identity/relationship validation, preservation tests, pinned native-preview identity, a shared root player, and a loopback synthetic-media compatibility proof.

## Listening unit and decision

Recommend individual tracks as the next owned listening unit, entered from a release. It matches browse → release preview → identify → Bandcamp support, makes track identity explicit, and lets editors validate availability one item at a time. The implemented public native-preview journey now persists across ordinary internal navigation: one root-layout client provider owns the media while pages and the compact/expanded view change. Selecting another release stops/replaces the current preview; track end and full page departure/reload end playback. The owner explicitly authorized this persistence, superseding the earlier stop-on-route-exit recommendation. No queue, scheduled station or synchronized audience was added. Owner confirmation of the future owned listening unit remains pending.

**Play preview** starts the selected release without navigation. Artwork retains its release-detail destination; **Visualizer** expands the existing player, **Browse** returns to the archive, and **Credits** opens metadata/credits/notes from the same effective `Release`. Credits retain supplied role/name text and multiline formatting; missing credits are explicit. The informational track list does not imply per-track play controls or inferred track credits. **Full release page** closes the drawer and navigates internally without replacing the audio source. The optional official embed remains a separately chosen alternative with independent controls; native persistence does not establish parent control or observation of iframe playback.

Rights are a prerequisite per recording: owner/license, authorized territories, term, permission to encode/host/serve, and takedown contact. Public Bandcamp-preview eligibility does not grant Hochi permission to ingest or redistribute it. Import metadata only. Do not use those URLs as owned media assets. Recorded sessions would require a session entity, ordered cue sheet, contributor/recording rights and duration handling. A continuous program would additionally require schedule/version/clock, current-position semantics, failure programming, rights for each play, and an operator; neither is justified by the current journey.

## Relationship model

Use a relational model with opaque immutable UUIDs assigned once and retained independently of names and remote slugs. Proposed SQL implementation is PostgreSQL-compatible, not a vendor commitment. Import IDs use a versioned deterministic namespace + immutable source kind/ID where established; legacy IDs have a reviewed mapping manifest before any backfill. Never merge identities by spelling. Keep existing public release/artist slugs as unique immutable route aliases; redirects need explicit approval and regression checks. Catalog number is an editorial unique reference, not an upstream title.

Minimum states: draft/published/archived for editorial records; proposed/confirmed/rejected for relationships; pending/available/unavailable/revoked for media. Public projections require a published parent release and, when track_id is present, its published track; confirmed associations feed profile links, and available/authorized media is required for owned playback. Owned progressive/HLS track delivery requires a non-null track_id belonging to the referenced release and a valid RightsGrant. Official embeds retain a nullable track_id and honest release-preview identity because the parent cannot observe the currently playing track. A Bandcamp preview without a reliable archived track identity also stays release-level until reconciled; never fabricate a track association to fill this field. Unresolved artist credits remain credited text, never an automatically published relationship. An artist-only CMS authoritative empty list must not resurrect unpublished records.

Implementation constraints: FK integrity, nonempty slugs matching existing route rules, unique source identities, credit/sequence ordering, no duplicate profile release results, bounded duration, approved HTTPS link origins, no query-bearing credentials, and no imported raw media objects. Availability and publication are separate: a release stays browsable when its media is unavailable. Publisher writes a versioned read model and validates it transactionally; website reads that model through the current adapter boundary until parity is established.

## Playback contract

A proposed owned-media resolver accepts release/track immutable identity, checks publication/availability/rights, and returns `{releaseId, releaseSlug, trackId, identityLevel, mediaId, mediaVersion, title, creditedArtists, artwork, supportUrl, deliveryKind, duration, availability, playbackLocator}`. Owned track delivery requires trackId and identityLevel `track`; a release-level official embed or unresolved external preview uses trackId `null` and identityLevel `release`, with explicit release-preview labeling. Never accept an arbitrary URL from a browser. The same resolved record drives player text, artwork, support and audio. Version/pin prevents later resolution from silently playing different native/owned audio; it does not claim control over an official embed's internal track selection. Unavailable/revoked/version mismatch returns an explicit recovery state; no first-release fallback. Locator is bounded/short-lived if authorization is needed. Identity may be public even when media cannot be played.

Today's shared native player implements the smaller version of this principle: sanitized selected-track identity plus a same-origin fingerprint-pinned stream path. If Bandcamp changes its selected preview between metadata and stream lookup, playback refuses rather than mislabeled audio. Credits use the full effective release record passed alongside that selection; release credits are not recast as the playing track's contributors. The official embed cannot be observed for precise playing track by the parent; show release-preview identity and allow Bandcamp's own controls/track labels. Never claim that an embed provides analyser samples or that opening either route proves playback.

| Option for approved individual tracks | Delivery/maintenance | Why/when |
|---|---|---|
| Progressive MP3/AAC over HTTPS with byte-range requests | One encoded file + approved storage/CDN, Range/HEAD/content headers, CORS where separate origin, cache/version/takedown; use one HTMLAudioElement routed through one AudioContext/analyser/gain/destination | Recommended initial owned-media path: lowest operational complexity for short on-demand tracks; seek and track-end semantics fit current player |
| HLS VOD | Encode/segment/package playlists, variant sets, player integration/native vs MSE compatibility, CORS for every resource, playlist/segment cache consistency and monitoring | Consider if measured network/long-session needs justify adaptive delivery; not a prerequisite for this journey |
| HLS live | Above plus encoder uptime, schedule/cue metadata, program operator, lag/clock recovery and listener-position rules | Requires an approved continuous program; adds requirements not supplied by HLS alone |

[Apple's HLS documentation](https://developer.apple.com/documentation/http-live-streaming) describes HTTP segments/playlists and adaptive variants. That transport does not supply Hochi's archive model, queue, rights, programming, identity, shared clock, or renderer. [MDN's MediaElement source documentation](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaElementSource) describes routing one media element into Web Audio. A separate delivery origin must allow the requesting website through CORS before analyser playback is accepted; test the exact CDN/codec path. No vendor or bandwidth/cost estimate is inferred from references.

## Executed compatibility proof and next gate

Run with Node 22: `node scripts/media-compatibility-server.mjs`; only `127.0.0.1:3002` is bound (override unprivileged port with `MEDIA_POC_PORT`). The test serves generated six-second PCM WAV, supports byte-range/HEAD, transpiles the **actual** stream-audio class and renderer from this checkout, and opens `docs/remediation/media-compatibility.html`. No catalog file/media is stored, no upload feature is introduced, and it is outside production routes. At least one real browser showed Playing with changing time and nonzero low-band analyser samples; pause zeroed the sampled bands; seeking to 4 seconds moved media position. Exact final browser/end/resume evidence is in verification.md.

This establishes a local synthetic progressive-media path through the current player/analyser/renderer. It does **not** prove hosted MP3/AAC/HLS, remote CORS, device interruption, rights, catalog-wide availability, or a shipped delivery service. Next test after rights/delivery approval: one authorized MP3/AAC source served by selected staging CDN; verify codec support, exact CORS, bytes/Range/HEAD/timeouts, gesture play/pause/resume/seek/end, media-version identity, interruption/resume, internal-navigation continuity, rapid release replacement/full-exit teardown, no-WebGL/reduced motion, and Safari/Chromium/iOS/Android. Compare an HLS candidate only if journey/measurements require it. Record request headers and browser evidence without signed tokens.

Required responsible roles (unassigned): label editor (identity/copy/relations/publication), rights owner (media grants/revocation), technical operator (imports/CDN/recovery/monitoring), release approver (cutover/browser matrix). Owner must name people before production. Import failures preserve prior published metadata and produce visible CI/operator failures; delivery failures disable only media and retain archive/support links. Vendor commitment, media ingestion, production database migration and editorial-tool replacement remain approval gates.
