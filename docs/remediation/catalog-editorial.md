## Publishing and refresh rules

1. In local mode, `releaseArchive` is the editorial source. Add approved `memberSlugs` explicitly using stable roster slugs. Preserve `slug`, `code`, `bandcampType`, and `bandcampId`. For imported-only records, first add a curated archive entry carrying the existing BC code/site slug/source ID; otherwise grid removal intentionally removes the uncurated record. Never edit generated `bandcamp-catalog.json` as a relationship database.
2. In artist-only WordPress mode, published managed artists overlay the local roster. The catalog relationships remain local; this mode has no full release-overrides UI. Keep managed website slugs stable. Published biography/portrait changes use the normal Posts fields and the adapter's supported mappings.
3. In full bridge mode, an artist's saved `releaseSlugs` is authoritative, including an intentionally empty list. If omitted, effective release `memberSlugs` supplies its profile list. A published release override's omitted `memberSlugs` inherits; `[]` deliberately clears. The plugin synchronizes inverse associations only on existing published records the editor can edit. Use an Editor/Administrator for shared ownership; verify both artist profiles and release context after saving.
4. For a newly approved Hit Dat association, select the exact `hit-dat` release for AMAL and DJ Swisha and check both inverse views. Do not merely change the display `artist` string. Verify `/roster/amal`, `/roster/dj-swisha`, and `/releases/hit-dat`; refreshing the public picker must preserve the saved selection. The local approved fixture proves selection behavior, not a hosted save session.
5. Updating/reimporting the corrected plugin seed **does not rewrite existing records**. Earlier bundles inferred selections and published placeholders. An owner reviews existing choices and old copy deliberately; a difference from the new seed is not proof an existing editor choice is wrong. Preserve subsequent owner approvals.
6. Before each approved edit, record the published selections/copy and stable URLs. On failure, restore those prior values and republish. A refresh failure must retain the previous snapshot/catalog. Merge identity conflicts now fail visibly for manual review instead of choosing one source silently.

Bandcamp remains public metadata and preview infrastructure. No audio was downloaded, stored, redistributed, or imported into WordPress. Snapshot imports do not run per visitor. No checkout, new roster member, invented biography, fabricated portrait, or unapproved policy was created.
